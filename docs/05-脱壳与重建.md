# 技术文档：从 Enigma Protector 5.x 还原 enigma 原程序

本文记录完整原理、关键地址与可复现配方。所有结论均在本机实测验证。

> **说明（本项目更新）**：本文中的「配方输入」（`build\app_img_oep.bin`、
> `build\data.dpm.plain`、`scene*.hsp`）在本项目里**不需要事先准备**——
> 由 `extract\extract_oep.py`、`extract\extract_script.py`、
> `extract\extract_scene.py` 直接从 `crackme.exe` 与运行中的进程里取出；
> 一键入口是根目录的 `run_all.py`（或 `一键脱壳重建.bat`），
> 构建脚本位于 `build\`。下面的配方仍准确描述每一步在做什么。

---

## 1. 目标与结果

- 目标文件：`bk\crackme.exe`（9,927,144 B，Enigma Protector 5.x 加壳，
  内部是 enigma 的 `unenigma.exe`，HSP3 运行时）。
- 结果：得到**无壳**的 `unenigma.exe`（347,136 B）
  + 脚本库 `data.dpm`（14,362,670 B）+ 替代 `unixTime.dll`（6,487 B），
  可直接运行，窗口标题 `目标程序窗口`。
- 其中**唯一被 Enigma 虚拟化**的原程序函数是 `WinMain`，其余代码原样保留。

---

## 2. 原程序的定位（静态 + 动态交叉验证）

对原程序映像（运行时映射在 `0x400000`）做同步反汇编，指向壳映像
（`0x453000..0xC32000`）的直接 `call/jmp` **只有一处**：

```
0x41AFF0: e8 8f fb 18 00     call 0x5AAB84     ; -> 壳的 VM 跳板
```

即只有 `WinMain`（`0x41AFF0`）被替换成了 VM 桩。其余 340 KB 指令流完整。

## 4. 七个关键技术点

| # | 现象 | 结论 / 修复 | 脚本 |
|---|---|---|---|
| 1 | WinMain 是 VM 桩 | 用 HSP3 3.5 源码语义重建：<br>`res=hsp3win_init(hInstance,NULL); if(!res) res=hsp3win_exec(); return res;` | `restore_winmain.py` |
| 2 | 入口点判错 | 真实入口是 `0x4209E9`（`__scrt_common_main_seh`），不是 `0x4204BF` | — |
| 3 | 改写入口导致崩溃 | **不能覆写 `0x4204BF` 的指令**（CRT 内部会调用它），<br>必须改写 PE 的 `AddressOfEntryPoint` 指向代码洞 | `add_entry.py` |
| 4 | `.data` 被异步改成只读 | 启动时该区间（`0x401000..0x44E000`）被设为 `PAGE_EXECUTE_READ`；<br>入口桩 `Sleep(120)` + 两次 `VirtualProtect(PAGE_READWRITE)` 抢在竞态之前 | `add_entry.py` |
| 5 | **导入槽 `0x43C154` 映射错** | 真身是 **`KERNEL32!CloseHandle`**（`0x4205EA` 传入 `CreateEventW` 句柄；`0x42D6AD` 传入 `_fileno` 句柄），<br>不是 `RtlEnterCriticalSection`。改对后 CRT 完整初始化、程序进入自身代码 | `build_exe.py` |
| 6 | 缺 TLS 目录 | 程序用 msvcrt 风格静态 TLS（`mov eax,fs:[0x2C]` + `_tls_index@0x44DFB8`），<br>重建 PE 时补上 TLS 数据目录 | `add_tls.py` |
| 7 | **脚本被再次 XOR 解密** | 运行时会用固定 0x47 字节 pad XOR 整个脚本（构建名 `hsprt-XOR-eg`）；<br>内存里 dump 出的是明文，所以存储时必须**预 XOR** | `build_dpm.py` |

## 5. 脚本解密 pad（`hsprt-XOR-eg`）

`Hsp3::Reset` 在 `0x401F10` 的循环对 `[esi, esi+ebx)` 逐字节做
`xor [ecx+esi], al`，`al` 取自 `.rdata` 的固定表，索引按 `0x47`（71）回绕。
其中：

- `esi` = `0x4018F0(名)` 返回的**刚读入的整份脚本缓冲**；
- `ebx` = `0x401280(名)` 返回的**该文件大小**；
- pad 索引从 **该缓冲的第 0 字节**开始计数。

**结论（重要）**：XOR 只作用于 `Reset` 加载的那一个文件（`start.ax`），
**不是**整个 DPM 数据区。因此当 DPM 里还有别的文件（`scene1.hsp` 等）时，
这些文件必须按**明文**存放；只有 `start.ax` 预 XOR。

pad 的求法：在一次运行中，分别在解密循环**前**（`0x4019D8`）和**后**
（`0x401F49`）采样同一缓冲（0x47 字节），`pad = pre ^ post`：

```
cdeb2d4724fc454281ca53f143772af50e01b0e3cf21fd7e39dc1e9ccfc185b6
bec12e1f41c65ee3c2ea1863a459387bb1df3f773a27bc94d5927241e0d3170
18b21c9f3a91830
```

存储关系（**脚本数据起始**算起）：

```
stored[i] = plaintext[i] ^ pad[i % 0x47]
```

## 6. 脚本库 DPM 与单文件打包

### 6.1 DPM 格式（`0x401A30` 反汇编确认）

```
+0   'DPMX'
+4   u32 optr      = 16 + 32*dent        （数据区起始，相对 DPM 头）
+8   u32 dent      （条目数）
+12  u32 namsize   （一般为 0）
+16  条目表，每条 32 字节：
        +0   name[16]    文件名（\0 结尾，最长 15 字符）
        +16  u32         0xFFFFFFFF
        +20  u32         per-file key（0）
        +24  u32         数据区内的偏移
        +28  u32         文件大小
+optr 数据区（各文件按 +24 偏移排布）
```

目录是**线性查找**（逐个比对名字），所以条目顺序无所谓；
HSP 的读文件流程是**先查 DPM、查不到再回退磁盘**。

### 6.2 本项目的 DPM 内容

```
start.ax      14,214,309 B   预 XOR（明文是内存里 dump 出的脚本）
scene1.hsp       145,508 B   原版正文（去掉 ;### 注释头，89 个 {end}）
scene2.hsp         2,661 B   原版正文（英文分支；中文版只读 scene1）
```

把 `scene1.hsp` 放进 DPM 后，程序不再需要外部 `scene1.hsp`，
单文件版真正做到只需 exe（外加必须的 `unixTime.dll`）。

### 6.3 单文件（HSP “打包 exe”模式）

HSP3 运行时的行为（`hsp3win_init` / `Hsp3::Reset`）：

- `optmes[]` 8 个字符全不等于模板签名 → 认为“已打包”，
  读取 pack 字段并调用 `SetPackValue(sum, dec)`；
- `Reset(mode!=0)` → `dpm_ini("", dpmofs=mode, chksum=sum, deckey=dec)`，
  其中 `mode = atoi(optmes+9) + 0x10000`；
- DPM 从**自身 exe** 的 `dpmofs` 处读取。

因此单文件版做法：把上面的 DPM 追加到 exe 末尾（4K 对齐处 `O`），
再改写 `.data` 的 36 字节 `optmes`（文件偏移 `0x4B48C`）：

| 偏移 | 值 |
|---|---|
| 0..7 | 0（使签名不匹配 → 进入打包模式） |
| 9.. | `str(O - 0x10000)` 的十进制 ASCII |
| 17 | 0（非屏保） |
| 19 | `'x'`，20（short）窗口宽 |
| 22 | `'y'`，23（short）窗口高 |
| 25 | `'d'`，26（short） |
| 28 | `'s'`，29（short）= DPM 校验和（`Σdpm[i] & 0xFFFF`，seed=0） |
| 31 | `'k'`，32（int）= 解密 key（0） |

见 `build\build_singlefile.py`。

## 7. 剧情脚本 `scene1.hsp` / `scene2.hsp`

- 由 `main.hsp` 的 `#pack` 打包，不在 `start.ax` 里，**必须单独提供**。
- `scene.hsp` 里是 `noteload lang("scene1.hsp", "scene2.hsp")`：
  `lang(日文, 英文)`，`config.txt` 的 `language."0"`（中文）走日文分支，
  → 中文版**只读 `scene1.hsp`**。
- 格式：`{0}`、`{1}`… 编号场景；指令 `{pic} {mc} {txt} {chat_N} {actor_N}
  {se} {fade} {fadein} {wait} {end}`；文本为 **GBK**。
- 这份脚本必须**带 `{0}` 序章**。游戏播放序章时，内存里的 `{0}` 区可能被后续
  分配覆盖；`extract\extract_scene.py` 会用残留的 `{txt}` 正文尽力补回，并且
  **只接受**以 `{0}` 开头、含 89 个 `{end}` 的完整文件——缺序章的半截文件会被
  判失败，`run_all.py` / `build_dpm.py` 也会拒收，避免出现「创建角色后
  HspError 12 崩溃」。
- **从零重建时**：`run_all.py` 会**启动一次原程序**，把 Enigma 虚拟文件系统里
  映射出来的 `tmp\scene1.hsp` / `scene2.hsp` 直接用 HSP 自己的读文件函数
  （`0x4018F0`，见 `extract\extract_scene.py`）读出来——**原版字节**，含一行
  `;###` 注释头。**不需要 `data.dpm`，也不用进游戏**：这两个文件磁盘上不存在，
  只存在于壳进程的虚拟文件系统里。删掉 `tmp\` / `out\` 都能重建；连
  游戏目录里旧的 `data.dpm` 也可以删掉。
- 取不到虚拟文件时才依次退回：游戏目录 `data.dpm`（`--from-dpm`）→
  `tmp\` 里的真实文件 → 进游戏扫描内存。

## 8. `unixTime.dll`

- 原 DLL 是中文 LTS 整合版自己加的（原版 xxxx 的 `#uselib` 里没有），
  原文件被 Enigma 虚拟化，磁盘上没有。
- 脚本里只用到 **`calcTimeDiffe1`**，用于**自动备份存档**的时间戳命名
  （`3_SaveBackUp`，格式 `%04d_%02d_%02d_%02d_%02d_%02d[_%03d]`）。
- 该函数语义（从内存 dump 出的原 DLL 反汇编得到）：

  ```
  calcTimeDiffe1(y, mo, d, h, mi, s)
      = (int)( time(NULL) - mktime(local(y, mo, d, h, mi, s)) )
  calcTimeDiffe2(...) = 上式取负
  ```

- 本项目用 `scripts/unixtime/unixtime.s`（x86 汇编，只用系统 `msvcrt.dll`
  的 `_time32` / `_mktime32`）重新实现，导出名与原 DLL 一致
  （`GetNowUnixTime` / `calcTimeDiffe1` / `calcTimeDiffe2` / `fnunixTime`）。
  自测：`calcTimeDiffe1(2026,10,18,12,0,0)` 与 Python 的
  `time.time()-time.mktime(...)` 结果一致。
- 注意：DLL 入口必须返回 `TRUE`，否则 `LoadLibrary` 报
  `ERROR_DLL_INIT_FAILED (1114)`；本项目为此提供 `_DllMainCRTStartup`。

## 9. 完整配方

```bat
:: 前置（实际由 run_all.py 现场提取，无需手工准备）：
::   app_img_oep.bin      OEP（CRT 运行前）原程序映像
::   start.ax             运行进程里的明文脚本主体
::   scene1.hsp scene2.hsp 剧情脚本（完整、含 {0} 序章）
python run_all.py --verify
```

`run_all.py` 依次执行：

1. `build_exe.py` — 用 OEP 映像重建 PE、重建导入表
   （并**丢弃落在 `.text` 内的伪 IAT 槽** `0x202A0/0x25288/0x34160`）；
2. `restore_winmain.py` — 在 `0x41AFF0` 写入原生 WinMain；
3. `add_entry.py` — 写入口桩（Sleep + 双 VirtualProtect + heap 修复 +
   `__security_init_cookie` + 跳 `0x4209E9`），并改写 `AddressOfEntryPoint`；
4. `add_tls.py` — 写入 TLS 数据目录；
5. `add_scene_boot.py` — 追加 `.scn` 段（内嵌 `scene1/2.hsp`），并把入口指向
   启动桩：先写 `%TEMP%\scene1.hsp` / `scene2.hsp`，再跳回原入口
   （原版由 Enigma 虚拟文件系统提供这两个文件）；
6. `build_dpm.py` — 构造脚本库（`start.ax` 预 XOR + `scene1/2.hsp` 明文）；
   剧情脚本不完整（缺 `{0}` 序章）会直接报错，不再产出会崩的包；
7. `build_singlefile.py` — 生成内嵌 DPM 的单文件版；
8. `build_unixtime.py` — 重建 `unixTime.dll`（需要 binutils，缺则跳过）。

> 顺序很重要：`.scn` 必须在 `build_singlefile.py` **之前**加入，否则追加的 DPM
> 会把文件偏移改变，HSPHED 里的 `mode`（DPM 偏移）就失效了。

构建是确定性的：同样输入两次构建，产物逐字节一致。

## 10. 如何得到 OEP 映像、明文脚本与剧情脚本

（本项目已附带；如需从头再取）

- **OEP 映像**：给壳进程的 `WinMainCRTStartup` 之后、`__scrt_common_main_seh`
  之前设硬件断点（DR0=`0x4209E9`），单步异常时用 WER LocalDumps 抓全量转储，
  再提取 `0x400000..0x453000`。
- **明文脚本**：从正常运行的游戏进程内存里定位 `HSP3` 对象
  （`HSPHED.allsize` 为长度），导出即 `start.ax`。
- **剧情脚本**：原壳把 `scene1.hsp` / `scene2.hsp` 放进自己的虚拟文件系统，运行时
  映射为 `tmp\scene1.hsp` / `tmp\scene2.hsp`（磁盘上看不到）。启动原程序后，
  用 HSP 自己的读文件函数读出即可（**不需要进游戏**）。退路：从现成 `data.dpm`
  取（`--from-dpm`），或在进剧情时扫描内存；结构不完整（缺 `{0}`）就判失败，
  不会写入 `tmp\work\`。

## 12. 边界与说明

- 不修改 `crackme.exe`；不含游戏资源文件；需与游戏目录一起使用。
- 仅适用于本机这份 HSP3 3.5 / `hsprt-XOR-eg` 构建；
  其他版本的 pad 与操作码不同，需按第 5 节重新求 pad。
- `unixTime.dll` 必须与 exe 同目录（HSP 用 `LoadLibrary` 加载，无法从 DPM 取）。
- 仅供个人已授权副本或安全研究使用。
