## 2. 进程与内存访问

启动器只使用 `kernel32` / `user32` 的标准 API：

```python
h = OpenProcess(PROCESS_VM_READ | PROCESS_VM_WRITE |
                PROCESS_VM_OPERATION | PROCESS_QUERY_INFORMATION,
                False, pid)
ReadProcessMemory(h, addr, buf, size, &got)
WriteProcessMemory(h, addr, buf, size, &got)
VirtualQueryEx(h, addr, &mbi, sizeof(mbi))   # 扫描映像基址
```

- 不需要管理员权限（游戏是普通用户进程）；
- 不注入 DLL、不创建远程线程、不修改任何线程上下文。

### 映像基址的探测

```python
def markers_ok(mem, base):
    m1 = read_u32(base + OFF_SAVE)
    m2 = read_u32(base + OFF_MSG)
    return (m1, m2) if (m1 in MARKERS and m2 in MARKERS) else None
```

1. 先试 `0x453000`（实测值，命中率 100%）；
2. 否则遍历 `VirtualQueryEx` 的所有已提交区域，找标记匹配的基址；
3. 都失败则仍返回 `0x453000`（并在日志里标注「与预期不同」）。

## 3. 两个描述符的语义

| 偏移 | 初始标记（实测） | 改成 | 效果 |
|---|---|---|---|
| `0x07615A8` | `0x2C`（偶见 `0x2D`） | `0x03` | 虚机判定「保存许可 + 启动原程序」为真 |
| `0x075AF1C` | `0x2C`（偶见 `0x2D`） | `0x03` | 虚机判定「显示成功消息」为真 |

注意：

- 标记不是固定的 `0x2C`，实测出现过 `0x2D`、`0x44` 等；
  启动器不依赖具体初始值，只写入 `0x03`。
- 两个描述符必须**同时**改才完整（见 01-原理 §5）。

## 4. 窗口自动化

### 4.1 枚举

`EnumWindows` + `EnumChildWindows`，按 `GetClassNameW` / `GetWindowTextW`
匹配：

| 用途 | 匹配规则 |
|---|---|
| 注册对话框 | 类名含 `TEnigmaProtectorLoaderRegistrationForm` |
| 用户名输入框 | 类名含 `LoaderEdit`（取最下面那个） |
| 密钥输入框 | 类名含 `LoaderMemo` |
| 注册按钮 | 类名含 `LoaderButton` 且文本 `注册` |
| 成功框 OK | 类名含 `LoaderButton` 且文本 `&OK` |
| 游戏窗口 | 类名 `hspwnd0` 且标题含 `目标程序窗口` |

### 4.2 填字

```python
SendMessageW(hwnd, WM_SETFOCUS, 0, 0)
for ch in text:
    SendMessageW(hwnd, WM_CHAR, ord(ch), 1)
```

### 4.3 点击

```python
PostMessageW(hwnd, BM_CLICK, 0, 0)   # 不是 SendMessage！
```

原因：按钮的处理函数会在**调用线程内**跑虚机校验并弹模态框；
`SendMessage` 会一直阻塞到模态框关闭，导致脚本卡死。
`PostMessage` 把点击排进目标窗口的消息队列，立即返回。

## 5. 完整调用流程

```
main()
 ├─ 环境检查（crackme.exe 是否存在）
 ├─ 已有游戏/对话框窗口？→ 直接返回 0
 ├─ Popen(crackme.exe, cwd=free)
 ├─ 循环等对话框（≤20 s）
 ├─ sleep(1.2)                     # 跳过完整性校验
 ├─ base = image_base(mem)
 ├─ write(base+0x07615A8, 0x03)
 ├─ write(base+0x075AF1C, 0x03)
 ├─ 填用户名（默认 "enigma"）+ 假密钥
 ├─ PostMessage(注册按钮, BM_CLICK)
 └─ 循环（≤40 s）
      ├─ 若出现 "&OK" 按钮 → 点它
      └─ 若出现 hspwnd0 且标题含 launcher.json 里的 window_title → 成功返回 0
```

## 6. 实测时序

| 时间 | 事件 |
|---|---|
| 0.00 s | 启动 `crackme.exe` |
| 0.20 s | 注册对话框出现 |
| 1.40 s | 等待结束，开始打补丁 |
| 1.46 s | 两个描述符写入完成 |
| 1.75 s | 填完用户名/密钥 |
| 1.80 s | 点击「注册」 |
| 2.21 s | 点击「成功注册」的 OK |
| 3.81 s | 游戏窗口出现 |

> 时间会随机器负载波动；启动器内部使用「等窗口」而不是固定 sleep，
> 只有 `1.2 s` 是固定等待（完整性校验窗口）。

## 7. 返回码

| 码 | 含义 | 处理建议 |
|---|---|---|
| 0 | 成功（或已在运行） | — |
| 1 | 未捕获异常 | 看控制台 traceback |
| 2 | 找不到 `crackme.exe` | 检查目录结构 |
| 4 | 等不到注册对话框 / 进程提前退出 | 见 04-故障排查 |
| 5 | 找不到「注册」按钮 | 对话框可能被遮挡/改版 |
| 6 | loader 进程退出 | 看退出码 |
| 7 | 超时没等到游戏窗口 | 见 04-故障排查 |

## 9. 安全与稳定性说明

- 不修改磁盘文件；`license.s2` 是**壳自己**写出的。
- 不改变目标进程的执行流、不注入代码。
- 所有写入都是 4 字节数据；写入前用标记值确认基址，避免写错地址。
- 失败不会破坏游戏文件；重跑启动器即可。
