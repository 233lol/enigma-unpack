| 时间 | 映像基址 | 标记（save/msg） | 游戏窗口 | 结果 |
|---|---|---|---|---|
| 14:16 | `0x453000` | `0x2D / 0x2C` | `目标程序窗口` | exit 0 |

- 映像基址始终为 `0x453000`；
- 标记初始值可能变化（`0x2C` / `0x2D`），启动器不依赖它；
- 每次都在 3～4 秒内出现游戏窗口。

## 3. 反例证据（说明为什么必须等 1.2 秒）

### 3.1 过早打补丁

在对话框出现后 **约 90 ms** 就修改描述符：

```
Internal Protection Error
```

——壳的启动完整性校验还没结束，发现了内存改动。

### 3.2 改代码 / 跳转

把描述符处的虚拟指令流改成跳板（改变执行位置）：

```
立即被检测 / 进程终止
```

——壳校验执行位置，与字节校验无关。

### 3.3 只改一个描述符

只改 `0x075AF1C`：

- 消息变成「成功注册」；
- 但**不写许可、不启动游戏**；
- 点 OK 后进程以 `0x386xxxx` 退出。

只改 `0x07615A8`：

- `license.s2` 被写出（80 字节，只读）；
- 进程保持存活并进入游戏；
- 但消息可能仍显示「注册没成功」。

**结论：两个描述符必须同时改。**


（`hspwnd0` 是 HSP3 运行时的窗口类，说明原程序确实在运行。）

## 5. license.s2 的行为

| 项目 | 观察 |
|---|---|
| 路径 | `free\data\license.s2` |
| 大小 | 80 字节 |
| 属性 | 只读（壳设置） |
| 内容 | 壳用**假注册码**加密后的记录 |
| 下次启动 | 重新公钥校验 → 失败 → 再次弹注册对话框 |

因此启动器**不持久**：每次启动都要运行一次。
这是 RSA 签名机制决定的，无法通过改文件绕过（见 01-原理 §7）。

---

## 6. 失败码对照（实测）

| 现象 | 退出码 | 原因 |
|---|---|---|
| 游戏窗口出现 | `0` | 成功 |
| 等不到对话框 | `4` | 残留进程/异常 |
| 找不到注册按钮 | `5` | 窗口未就绪/被改版 |
| loader 退出 | `6` | 壳内部失败 |
| 超时无游戏窗口 | `7` | 判定失败或启动被拦截 |

---

## 7. 复现步骤

1. 确认 `free\crackme.exe` 存在；
2. `taskkill /F /IM crackme.exe` 清掉残留；
3. 运行 `一键启动游戏.bat`；
4. 观察控制台时间线（应出现 `游戏已启动`）；
5. `tasklist | findstr crackme` 应能看到进程；
6. 关闭游戏后进程消失，下次重复步骤 3。
