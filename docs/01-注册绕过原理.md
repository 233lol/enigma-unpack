# 01 · 原理：Enigma Protector 的注册判定与描述符机制

> 本文解释「为什么在注册对话框出现之后、改两个 4 字节的数据，就能让壳
> 走注册成功的分支」——这是整个启动器的理论基础。

---

## 1. 目标程序的结构

```
free\crackme.exe  (9,927,144 字节, PE32)
├─ 原 enigma 主程序的 PE 头 + 被加密/压缩的节
└─ Enigma Protector 追加的节（壳的 loader / 虚拟机 / 注册界面）
```

运行时：

| 区域 | 内容 |
|---|---|
| 主模块（`crackme.exe` 自身） | Enigma loader、注册窗口资源 |
| `0x453000` 起的额外映射（约 10.5 MB） | 壳的虚拟机数据 / 被保护的原程序映像 |
| 原程序映像 | 由壳解密后在**同一进程**内执行 |

注册对话框的窗口类：

```
TEnigmaProtectorLoaderRegistrationForm.UnicodeClass
TEnigmaProtectorLoaderEdit.UnicodeClass
TEnigmaProtectorLoaderMemo.UnicodeClass
TEnigmaProtectorLoaderButton.UnicodeClass
```

---

## 2. 启动阶段的时间线

```
[0.00s] CreateProcess(crackme.exe)
[0.00～0.30s]  ★ 启动完整性校验 + 反调试检查
[0.20s] 注册对话框出现（此时校验已经结束）
[1.40s] 对话框稳定，可以安全地改内存
```

**关键点**：完整性校验只覆盖**启动阶段**。
- 在对话框出现前（约 0.3 秒内）改动 → `Internal Protection Error`；
- 在对话框出现后再改 → **不会被复查**。

启动器里的 `WAIT_FOR_CHECK = 1.2` 秒就是为避开这段校验窗口。

---

## 3. 注册判定不是普通代码，而是虚拟机

Enigma 把注册判定**虚拟化**了：真实的判定逻辑不在 x86 机器码里，
而是在壳的**自定义虚拟机**中解释执行。

- 虚拟机指令流由壳在运行时解密、逐条解释；
- 因此你**看不到**「比较用户名/密钥」的普通汇编；
- 直接改机器码（比如把条件跳转改成 `jmp`）会被两件事发现：
  1. **完整性校验**（代码段哈希）；
  2. **执行位置校验**（虚机检测执行流是否偏离预期路径）。

这也解释了为什么之前所有「改代码 / 打跳板 / 下断点」的方案都会失败。

---

## 4. 描述符：虚拟机里的「条件标记」

虚拟机的条件分支不是 `jz/jnz`，而是读取一块**描述符数据**：

```
+0  指令/描述符类型
+4  标记（marker）      ← 决定条件成立与否
...
```

在注册流程里，两个描述符的标记初始值实测为 `0x2C` / `0x2D`（同一族标记）。
虚拟机的语义是：

| 标记值 | 含义 |
|---|---|
| `0x2B` / `0x2C` / `0x2D` … | 普通条件标记（按虚机规则求值） |
| **`0x03`** | **永不跳转** —— 强制走「顺序执行」的那条路 |

> `0x03` 是枚举中一个合法的「永不成立」值，不是随意编造的字节；
> 虚机读到它时不会报错，只会让条件恒假。

因为改的是**数据**而不是代码：
- 完整性校验不会命中（校验的是代码段/映像哈希，不是这块可变数据）；
- 执行位置不变（虚机仍按原路径跑，只是条件结果变了）。

---

## 5. 两个描述符的分工

| 描述符（映像内偏移） | 被哪条虚机指令使用 | 作用 |
|---|---|---|
| `0x07615A8` | 指令索引 **20686** | 守住「**保存注册信息 + 继续运行原程序**」这一段 |
| `0x075AF1C` | 指令索引 **19191** | 决定弹出「**成功注册**」还是「**注册没成功**」 |

各自的单独效果（实测）：

- 只改 `0x075AF1C`：消息变成「成功注册」，但**不写许可、不启动游戏**，
  点 OK 后进程以 `0x386xxxx` 退出；
- 只改 `0x07615A8`：会写 `license.s2`、进程保持存活并进入游戏，
  但消息可能仍显示失败；
- **两个一起改**：消息成功 + 保存许可 + 进入游戏。

启动器同时改两个，得到完整效果。

> 运行时地址 = 映像基址 + 偏移。映像基址实测为 `0x453000`
> （不是主模块的 `0x400000`）。启动器会先用标记值验证基址，
> 再回退到扫描所有可读区域。

---

## 6. 为什么点「注册」之后游戏会在同一进程里跑起来

Enigma 的流程是：

```
注册对话框
  └─ 用户点「注册」
       ├─ 虚机执行注册判定
       ├─ 判定成功 → 解密原程序映像 → 跳转到原程序入口
       └─ 判定失败 → 弹「注册没成功」→ 退出
```

也就是说，「解密原程序 + 运行」是**壳自己的后续动作**，
不需要我们额外加载任何东西。我们只是把判定结果改成「成功」。

---

## 7. 为什么许可文件不持久

点「注册」后壳会写出 `free\data\license.s2`（约 80 字节，只读属性）。
它的内容是壳用**我们随手填的假注册码**加密后的记录。

下次启动时：

```
读 license.s2 → 用公钥校验 → 假码必然失败 → 重新弹注册对话框
```

私钥只在作者的 keygen 里，因此**无法生成能通过校验的许可**。
这就是「每次启动都要跑一次启动器」的根本原因。

（每次启动后 `license.s2` 会被重新生成；它是只读的，启动器不碰它。）

---

## 8. 方案边界（什么能做、什么不能做）

| 做法 | 结果 |
|---|---|
| 改描述符数据（本方案） | ✅ 通过，且不被完整性校验发现 |
| 改机器码 / 打补丁到文件 | ❌ 完整性校验失败（`Internal Protection Error`） |
| 在注册判定处下断点/改 EIP | ❌ 执行位置校验发现 |
| 注入 DLL / hook | ❌ 同上，且更容易被反调试发现 |
| 伪造许可文件 | ❌ RSA 公钥校验，无私钥不可行 |

核心思想：**不碰代码、不碰执行流，只改虚机读取的数据**。
